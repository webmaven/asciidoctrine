= Architecture Decisions

== TCK ASG Structure Mapping

*Date*: 2025-05-22
*Status*: Accepted
*Related Issues*: #42

=== Context

The project needs to produce a TCK-compliant Resolved Abstract Semantic Graph (ASG). This requires a mapping from the internal AST nodes to a specific JSON structure defined by the official ASG schema.

=== Decision

We have converged the internal AST structure to match the ASG schema directly. Each node in `nodes.py` now implements a polymorphic `to_dict()` method that produces TCK-compliant output. Semantic resolution (attribute substitution, etc.) is handled by the `ASGResolver`.

The mapping follows the official AsciiDoc ASG schema (https://gitlab.eclipse.org/eclipse/asciidoc-lang/asciidoc-lang/-/blob/main/asg/schema.json):

[cols="1,2"]
|===
| AST Node | ASG Structure

| `Document`
| `{"name": "document", "type": "block", "blocks": [], "attributes": {}, "header": {}}`

| `Paragraph`
| `{"name": "paragraph", "type": "block", "inlines": []}`

| `Text`
| `{"name": "text", "type": "string", "value": "text content"}`

| `Span`
| `{"name": "span", "type": "inline", "variant": "strong|emphasis|code", "form": "constrained", "inlines": []}`

| `Section`
| `{"name": "section", "type": "block", "level": 1, "title": [], "blocks": []}`

| `List`
| `{"name": "list", "type": "block", "variant": "unordered|ordered", "marker": "*|.", "items": []}`

| `ListItem`
| `{"name": "listItem", "type": "block", "principal": [], "blocks": []}`

| `Listing`
| `{"name": "listing", "type": "block", "form": "delimited", "delimiter": "----", "inlines": []}`

| `Ref`
| `{"name": "ref", "type": "inline", "variant": "link", "target": "url", "inlines": []}`
|===

=== Rationale

The official ASG schema is the authoritative source for the structure of the Resolved Abstract Semantic Graph. Directly aligning the AST with this schema eliminates the need for a complex transformation layer, reducing maintenance burden and ensuring that the parser always produces spec-compliant output.

=== Consequences

- New node types added to `nodes.py` must follow the ASG schema naming conventions.
- The `to_dict()` method must be kept in sync with any updates to the official ASG schema.
- Semantic resolution logic (e.g., attribute substitution) is centralized in `resolver.py` and operates on the structured AST before final serialization.

== Inclusive Location Tracking

*Date*: 2026-02-16
*Status*: Accepted

=== Context

The AsciiDoc TCK expects inclusive location boundaries (e.g., a 5-character word starting at column 1 ends at column 5). Lark's default `end_column` is exclusive. Additionally, the TCK often excludes trailing newlines and whitespace from node boundaries.

=== Decision

We have implemented a systematic approach to location tracking:
1. **Inclusive End Columns**: All node locations use `end_column - 1` from Lark's metadata.
2. **Child-Derived Boundaries**: Instead of using the raw parent rule's metadata (which often includes trailing delimiters or newlines), we use `_set_location_from_children()`.
3. **Filtering**: The `_set_location_from_children()` method explicitly ignores `_NEWLINE` and anonymous (`__ANON_`) tokens when calculating the start and end of a node. This ensures that a Paragraph node ends exactly where its last text element ends.

=== Rationale

This approach provides the highest level of precision required for TCK compliance and avoids "off-by-one" errors that occur when grammar rules are designed for ease of parsing rather than strict boundary matching.

== Indented Block and Marker Support

*Date*: 2026-02-16
*Status*: Accepted

=== Context

Standard AsciiDoc allows many block elements (like lists and literal blocks) to be indented. Our initial grammar expected these markers at the start of the line.

=== Decision

We have updated block-starting terminals (e.g., `ULIST_MARKER`, `LITERAL_DELIM`) to support optional leading whitespace using consolidated regexes: `/[ \t]*(\*+|[-])[ \t]+/`.

=== Rationale

This aligns the parser with the official AsciiDoc Language Specification regarding indented literal blocks and flexible list formatting.
