Welcome to the official documentation for **Asciidoctrine**, a modern AsciiDoc parser for Python.

This documentation is self-hosted: it is rendered using Sphinx with our own `asciidoctrine.sphinx_ext` plugin!

== Features

* **Lark-based Grammar**: High-performance, pure-Python parsing using the Earley and LALR algorithms.
* **Semantic AST/ASG Convergence**: A type-safe representation aligned directly with the official Language ASG schema.
* **Two-Pass Resolution**: Centralized semantic resolution pass for attributes, includes, and comment stripping.
* **Advanced Location Tracking**: Highly accurate, child-derived start and end line coordinates on block nodes.
* **Sphinx Integration**: Full extension support allowing you to author documentation in AsciiDoc and build it natively using Sphinx.
* **TCK Compliance**: Fully compliant core suite matching the official AsciiDoc Technology Compatibility Kit.

== Architecture

[NOTE]
====
This section is a summary of our architectural approach. For full details, please refer to the xref:architecture[Architecture Overview].
====

The parser operates in a multi-pass pipeline:

1. **Source Parsing**: Lark processes the source text into a CST.
2. **Transformation**: Our `AsciiDocTransformer` converts the CST into a structured AST.
3. **Semantic Resolution**: Attributes, includes, and links are resolved by `ASGResolver` to produce the final, spec-compliant ASG.

== Project Roadmap

Asciidoctrine is actively moving towards full spec compliance. Our current roadmap status:

=== Completed Features
* **Foundations**: EBNF grammar, converged AST/ASG structure, and Pytest-integrated TCK harness.
* **Core & Advanced Blocks**: Sections, Paragraphs, Admonitions, Sidebars, Examples, and Quotes.
* **Document Infrastructure**: Headers, multi-pass attribute entry propagation/resolution, and includes.
* **Lists & Tables**: Ordered/unordered lists, complex nested/mixed description lists, and basic tables.
* **Developer Experience**: Listing metadata properties, verbatim block callout parsing/stripping, and child-derived inclusive location tracking.

=== Next Up
* Section ID auto-slugification and cross-reference resolution.
* Sphinx renderer visitor auditing and Pygments styling.
* TOC outline extraction.
