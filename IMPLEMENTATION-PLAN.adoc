== Executive Summary

This document outlines a two-part implementation plan to advance Asciidoctrine toward full TCK compliance:

1. **AST/ASG Convergence**: Refactor the AST node structure to match the ASG schema directly, so that resolution only performs semantic changes.
2. **Comprehensive Test Suite**: Expand test coverage beyond the 13-test TCK using multiple test sources.

Starting Point: `main` branch (`4637c1c`)

== Part 1: AST/ASG Convergence Refactor

=== Problem Statement

The current implementation has divergent structures:

* **AST** uses internal terminology (`Strong`, `BulletList`, `children`)
* **ASG** uses schema terminology (`span`, `list`, `inlines`)

This requires a complex transformation layer (`asg_visitor.py` or dual-mode `to_dict()`) that:

* Doubles maintenance burden
* Creates two different output formats to test
* Hides bugs in the transformation layer

=== Goal

Converge the AST structure to match the ASG schema so that:

* `to_dict()` produces ASG-compatible output directly
* Resolution pass only performs semantic changes (attribute substitution, cross-reference resolution)
* Single source of truth for document structure

=== Phase 1.3: Update Serialization

Single `to_dict()` method that produces ASG-compatible output:

[source,python]
----
class Node:
    def to_dict(self) -> Dict[str, Any]:
        """Serialize to ASG-compatible dictionary."""
        data = {"name": self.name, "type": self.type}
        
        if hasattr(self, 'variant') and self.variant:
            data["variant"] = self.variant
        if hasattr(self, 'form') and self.form:
            data["form"] = self.form
        if hasattr(self, 'inlines') and self.inlines:
            data["inlines"] = [n.to_dict() for n in self.inlines]
        if hasattr(self, 'blocks') and self.blocks:
            data["blocks"] = [n.to_dict() for n in self.blocks]
        if hasattr(self, 'items') and self.items:
            data["items"] = [n.to_dict() for n in self.items]
        if self.attributes:
            data["attributes"] = self.attributes
            
        return data
----

=== Phase 1.4: Create Semantic Resolver

The resolver performs only semantic changes on the already-structured ASG:

[source,python]
----
# src/asciidoctrine/resolver.py

class ASGResolver:
    """Resolves semantic elements in the ASG."""
    
    def __init__(self, document: Document):
        self.attributes = document.attributes
    
    def resolve(self, node: Node) -> Dict[str, Any]:
        """Convert AST to fully-resolved ASG."""
        asg = node.to_dict()
        return self._resolve_recursive(asg)
    
    def _resolve_recursive(self, asg: Dict) -> Dict:
        """Recursively resolve attribute references."""
        if asg.get("name") == "text":
            asg["value"] = self._substitute_attributes(asg["value"])
        
        for key in ["inlines", "blocks", "items", "principal"]:
            if key in asg:
                asg[key] = [self._resolve_recursive(child) for child in asg[key]]
        
        return asg
    
    def _substitute_attributes(self, text: str) -> str:
        """Replace {name} with attribute values."""
        import re
        def replace(match):
            name = match.group(1)
            return self.attributes.get(name, match.group(0))
        return re.sub(r'\{([a-zA-Z0-9_-]+)\}', replace, text)
----

== Part 3: Language Feature Expansion & Ecosystem Support

This part outlines the design, implementation, and verification roadmap for expanding the AsciiDoc feature coverage in `asciidoctrine`. This plan incorporates a rigorous multi-tiered testing strategy and integrates active resolutions for identified technical debt.

=== Multi-Tiered Testing Strategy

Every new feature implemented in this roadmap must be validated across four distinct testing tiers to guarantee absolute compliance, runtime stability, and rendering correctness:

1. **Unit Tests** (`tests/test_blocks_parsing.py`, `tests/test_inlines_parsing.py`):
* *Focus*: Verify grammar parses the syntax correctly, generating correct AST structure and properties.
* *Assertions*: Validate that nodes map directly to expected ASG fields (e.g., correct node names, types, and attributes).

2. **Functional (Pyodide) Tests** (`tests/test_functional.py`):
* *Focus*: Verify compilation and execution in Wasm environments.
* *Assertions*: Run the parser in Pyodide/Playwright/Chrome, asserting that the ASG serialization translates perfectly in the browser.

3. **End-to-End Rendering Tests** (`tests/test_docutils_backend.py`):
* *Focus*: Verify backend translation correctness.
* *Assertions*: Render AST/ASG nodes through the `DocutilsRenderer`, asserting that output matches valid Docutils node trees, classes, and XML representation.

4. **TCK Contributions** (`tests/tck_harness/`):
* *Focus*: Spec-compliance validation.
* *Assertions*: Create new compliance test cases that run successfully through the local TCK runner, formatted for easy upstreaming to the official Eclipse AsciiDoc TCK repository.

=== Priority 3.1: Completing Partial Implementations (Highest Priority)

These are features that have partial foundations in the grammar, parser, or backend, but are currently not fully compliant or comprehensive.

==== 3.1.1 Description Lists (dlist) with Nesting & Mixed Formatting

* *Current State*: Basic description lists (`Term:: Definition`) are supported. Mixed and nested description lists fail or skip.
* *Proposed Changes*:
** *Grammar* (`grammar.lark`): Update `dlist_description` to include `dlist` itself. Support indentation-based and multi-line descriptions.
** *Backend* (`docutils_backend.py`): Implement full visitor support for `DescriptionList`, `DescriptionListItem`, and `DescriptionListTerm` to handle nested blocks recursively.
* *Verification Plan*:
** *Unit*: Add tests for nested/mixed description lists in `test_blocks_parsing.py`.
** *Functional*: Add nested `dlist` tests in `test_functional.py` and run under Pyodide.
** *E2E*: Verify correct generation of docutils description list nodes (`nodes.definition_list`).
** *TCK*: Extract and verify the `dlist:mixed` test case from the skipped doctest corpus.

==== 3.1.2 Advanced Table Cell Formatting

* *Current State*: Basic tables parse rows/cells, but formatting prefixes (e.g., `2*>m`, `.3+^.>s`) raise errors or are ignored.
* *Proposed Changes*:
** *Grammar* (`grammar.lark`): Introduce table cell specifier parsing (colspan, rowspan, alignments like `^`, `>`, `<`, styles like `m`, `s`, `e`).
** *AST Nodes* (`nodes.py`): Store cell specifications in `TableCell` attributes.
** *Backend* (`docutils_backend.py`): Apply colspec widths, cell spanning (`morecols`, `morerows`), and text styles in docutils.
* *Verification Plan*:
** *Unit*: Test complex alignments and spans in `test_blocks_parsing.py`.
** *Functional*: Assert browser-side table rendering in `test_functional.py`.
** *E2E*: Verify cell spanning maps to valid docutils column/row span XML attributes.
** *TCK*: Extract and verify the `table:insane-cells-formatting` test case from skipped doctests.

=== Priority 3.2: Features for the `asciidoctest` Library (Next Priority)

`asciidoctest` is an interactive testing library that parses files, extracts Python source listings, and verifies execution results.

==== 3.2.1 Listing Block Attributes & Metadata Extraction

* *Proposed Changes*:
** *Grammar* (`grammar.lark`): Ensure `attribute_list` preceding a `listing_block` is parsed robustly.
** *AST Node* (`nodes.py`): Listing nodes must cleanly expose block attributes (like `title`, `id`, `language`, and custom positional/named attributes such as `doctest="skip"` or `doctest=True`).
* *Verification Plan*:
** *Unit*: Test attribute dictionary extraction on listing blocks.
** *E2E*: Assert docutils listing blocks carry custom attributes correctly.

==== 3.2.2 Callout Matching and Extraction

* *Required Features*: Extract raw code without callout markers (e.g., `<1>`), maintaining relationships with following callout lists.
* *Proposed Changes*:
** Ensure `inline_callout` is parsed and can be stripped programmatically.
* *Verification Plan*:
** *Unit*: Test callout list parsing and line matching.

==== 3.2.3 Source Location Tracking & Technical Debt Item 8 Resolution

* *Required Features*: Report exact file line numbers for failed interactive tests.
* *Technical Debt Resolution (Debt Item 8 - Location Logic Duplication)*: Currently, `_set_location_from_children` is duplicated across three files (`lark_parser.py`, `block_transformer.py`, `inline_transformer.py`).
* *Proposed Changes*:

* *Verification Plan*:
** *Unit*: Test that inclusive locations are accurate on `Listing` and `Literal` nodes.
